# 新增领域子 Skill 的契约

适用于新增或修订宽领域/细分领域模块。已有目录见 [domain-catalog](domain-catalog.md)。

## 何时新增

只有当该领域存在现有模块未覆盖、会改变提问或审查判断的稳定要求时新增。仅因行业名称不同、或有一份新专利，不应复制一套主流程。细分领域可以补充宽领域模块，但应明确覆盖差异、共同适用范围和冲突处理，避免继承链无限加深。

## 文件与内容

创建 `domains/patent-领域英文名/SKILL.md`，name 与目录同名，description 说明触发条件和易混淆边界，metadata.version 标明版本。正文只包含：

1. 与总览的关系、可组合模块及停止重复路由的条件。
2. 该领域需要额外收集的材料与适用条件。
3. 影响权项、说明书、图件或实验的领域区别。
4. 必要信息缺失时怎样保留问题、避免凭文献补造。
5. 输出如何映射到现有 13 项 checks 与支持记录。
6. 当前官方依据、核查日期与能力限制。

可参考任一现有子 Skill 的结构，但替换领域判断内容。不要复制事实契约、CLI、XML交接或通用法律全文。法律要求、写作建议和工具策略分清；支持未知/N/A，不把清单中的每项都变成每案必填。

## 合并与验证

在 [登记表](../domains/registry.yaml) 增加 owner、version、scope、exclusions、reviewed_on、status 和 quality_evidence，与 frontmatter 一致。experimental → validated 需要质量对照与专业复核，机器只检查结构及证据文件存在；目录检查或少数路由试验不足以升级。细分行业优先作为参考资料，只有稳定独特判断且有回归案例才拆模块。操作见 [维护工具](../docs/skills-maintenance.md)。

在目录登记相对路径；验证 name/description、所有链接、完整包依赖和无循环执行。嵌套目录不是标准强制的父子调用机制，本项目依靠主入口显式读取；单独安装子目录前必须打包共用依赖或重新设计入口，并真实验证宿主发现。

新增至少一个正例、易混淆反例和一个跨领域案例至评测集。结构检查不证明模型会正确路由；新会话用真实请求运行后记录选中路径、读取证据、产物和评分。没有完成盲测时状态保持“流程已定义，效果待验证”。资料按 [domain-corpus](domain-corpus.md) 管理。

当前 schema_version=1 的 content-review 不接收新的 checks ID。新领域的结论写进已有 checks.evidence；若未来需要强制结构化领域证据，应同时设计 schema 迁移、CLI 校验、旧案例兼容及回归，不能只改文档声称门禁增强。

维护时运行 `python tools/check_skills.py`；该工具检查主/子 Skill 元数据、目录覆盖、本地链接和案例引用。行为验证按 [评测协议](skill-evaluation.md)，模块间输出按 [任务交接](task-scope.md)。引入外部实现前记录仓库、具体路径、检视日期及可得的提交版本；复制代码或正文时另核对许可与保留署名。只借鉴方法也要标明来源，不能将海外专利写法直接提升为中国申请规则。

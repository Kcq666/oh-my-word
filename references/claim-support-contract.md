# 权项支持记录：文字覆盖与人工对应

适用：生成 content-review.json 后、执行 final/handoff 前。schema_version 仍为1，原有字段保留；不同措辞的支持记录补充下述字段。旧审查仍须按新检查重审，不能只刷新哈希。

## 两种可核验的索引方式

**直接文字对应**：feature.text 是本权项真实原文，description_quote 包含该片段且确实位于说明书；引用的已确认事实 quote 同样能覆盖该片段。不能把任何 verified ID 当成万能支持。

**不同措辞、综合概括或组合支持**：保留真实的权项、说明书、材料措辞；在 feature 内补充 support_basis，并为每个 fact_ids 成员给出 fact_links。每条包含 fact_id、source_quote、basis；source_quote 必须位于该事实已有 quote 内，basis 解释该条材料具体支持什么，support_basis 解释权项与说明书的整体对应、范围和条件。不要改写申请正文或来源来制造字符串相同。

```json
{
  "text": "获取传感器温度值",
  "description_quote": "读取传感器输出的温度数值",
  "fact_ids": ["F1"],
  "support_basis": "经实际复核，两种表述对应同一采集操作，温度对象及输出一致。",
  "fact_links": [
    {"fact_id": "F1", "source_quote": "获取传感器温度值", "basis": "本条原始材料记载温度采集，说明书展开其读取操作。"}
  ]
}
```

示例仅说明字段；真实案件须按真实材料填写，不能复制该判断为 pass。程序核对映射存在、引用完整、来源引文可定位；不证明 basis 的法律或技术判断正确。无关材料即使被强写对应理由，仍是人工审查错误，不能据此宣称支持成立。

## 正文覆盖

程序要求 features.text 的连续原文片段覆盖权项正文，忽略部分排版/句读和固定引导语。只有可与名称核对的纯主题/引用开头可被排除，前序技术限定保留；不认识的写法保守要求覆盖。多个领域共用这一份记录。

FINAL-COVERAGE 表示记录缺少正文索引，并非自动认定专利不合法。查看报出的片段，补齐逐特征记录并复核其说明书和材料支持；不要为消除报错删除必要技术特征。继承特征、概括范围、公开充分与单一性仍需审查者判断。

当前版本不自动拆分法律意义上的技术特征，不验证现实实验，不提供语义相似度评分或授权判断。文字覆盖和哈希有效只是完整性条件。

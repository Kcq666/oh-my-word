# 领域路由与合并规则

## 三个独立维度

- 申请类型：invention / utility / design；依据希望保护的内容，不按用户行业猜测。
- 技术贡献：主要改进在哪里，哪些辅助领域的约束会改变披露与审查。可多选，未确定则保留 unknown。
- 案件阶段：挖掘、初稿、申请前定稿、已申请后的修改/答复。申请后须核对原始披露及案件程序，领域模板不能授权加入新事项。

初读材料，提取“技术问题—手段—效果/外观要点”的来源片段，再查 [目录](domain-catalog.md)。如果只是材料中的背景词，不加载该词对应的模块。任务仅为排版且内容已定时，仅在发现内容风险时扩展领域分析。

## 记录与按需加载

在案件已有扫描摘要中增加路由段；无摘要时保存一个 case-context.md，不额外建立并行账本。记录：申请类型和阶段、主贡献及来源位置、选中 Skill 路径/版本、辅助领域及理由、置信程度及依据、未知信息、需特别处理的程序事项。置信程度用明确/暂定/未知，不能编造概率。

按路径读取选中的 SKILL.md，共用流程只加载一次。材料变化、保护主题变化或新证据否定路由时更新记录并重审受影响内容。明确的技术事实足以判断时直接继续；缺口影响申请类型或关键披露时才问具体问题。

此记录是 Agent 工作材料，当前 CLI 不解析、不哈希绑定它。审查时将所用 Skill 名、版本和决定性依据写入 content-review.json 的已有 checks.evidence；规则/路由变更要求重新审查是流程要求，尚非机器强制失效机制。

## 组合与冲突

- 机械夹爪结合视觉定位：结构贡献加载机械，视觉算法有实质贡献时再加载软件/AI；检查位姿坐标、力/运动约束与接口。
- 药液输注设备：机械/电子按贡献加载；若涉及诊疗方法或药物方案，再加载生物医药并核对保护客体。
- 医疗设备外观：先加载外观模块，产品用途仅帮助理解视图；除非另有技术申请目标，不扩展到算法和药物。
- 仅说“人工智能”“平台”“新材料”：不足以确定可专利方案，先补手段和实现信息，不能填出行业常见实施例冒充事实。

共用事实账本和术语表。主模块组织权项，辅助模块提供必要条件与接口支持；不能把领域名字叠加当成创造性，也不能仅因有多个模块就建议拆案。按一个总的发明构思及具体技术关联分析单一性。

冲突先核对来源与适用条件；统一的是技术关系和术语，而非删除不利事实。现行中国规则优先于过期范例；领域写法不得放宽事实边界及交付门禁。无证据解决的冲突保留为问题，不自动选择更容易通过的说法。

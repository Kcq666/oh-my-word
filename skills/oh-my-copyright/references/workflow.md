# Fokkyp流程的本地适配

原始规则和执行脚本直接纳入 word_skills/_vendor/fokkyp，版本、提交和逐文件哈希以 UPSTREAM.json 为准。copyright workflow 在隔离子进程运行上游，避免 common 等脚本模块污染宿主。

保留上游阶段：项目证据→模型业务理解→源码候选与理由→申请信息与手册→截图清单→Word交付。prepare实际执行前三个证据阶段；select导入同一上游选择，绑定原件哈希。Agent负责判断和真实操作，不让关键字表替代业务理解。

本地差异：沿用现有Word后端；CLI用 --interface cli 将GUI句式改为命令和终端反馈；没有真实配套文档时不自动创建“总体设计、详细设计、测试案例”；缺事实可用 --preview继续起草，不能伪造确认；已确认的业务内容一旦变化必须重新审阅。发现阶段额外排除凭据、依赖目录和越界符号链接。未知扩展名只是待审阅候选。

手册需要真实场景、操作和结果。上游机械自检不能证明语义正确，也不能把重复渲染称为多轮独立评审。只有真实存在的设计资料可以列入相关文档。CLI的命令标识、参数、回显保持原样，不为了“去技术化”改写命令。

图文制作使用 markdown-it-py 解析现成Markdown，保留章节和表格。独立命令块采用等宽字体；图片必须是CASE内已声明的PNG/JPEG，制作时复制并绑定到审计，篡改使检查失效。图片路径相对CASE。DOCX/PDF输入的既有手册继续按已提取文本转录，不宣称可还原其原始版面。

所有权属、日期、开发环境等均按真实填写；上游经验建议不代替当期官网规则。源程序量是明确登记范围内的全部原始程序行数；交存页数是实际渲染的页数，不能用前后节选行数或估页替代。保留源码原文及第三方许可，不修改时间或依赖链接规避审查。
